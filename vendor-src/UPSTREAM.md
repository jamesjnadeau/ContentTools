# Upstream provenance of the vendored ContentEdit bundle

**Status: VERIFIED — the vendored bundle is byte-identical to upstream and contains no local
patches.** Established during Phase 0 of the 2.0 modernization. This closes the "Critical" risk
that absorbing ContentEdit would silently discard a local fix.

## Result

```
md5(first 5560 lines of build/content-tools.js) = 02110d6c67fcec34a8ce13d68241be10
```

Those bytes used to be duplicated at `external/scripts/content-edit.js`. The build now compiles
them from `vendor-src/`, so the duplicate is gone; the frozen v1.6.16 artifact still carries them
verbatim and is what the check compares against.

The same md5 is produced by (a) upstream `GetmeUK/ContentEdit@1.3.5`'s committed
`build/content-edit.js`, and (b) a from-source rebuild using the recipe below. Reproducing from
source matters more than the file match: it means every step of the CoffeeScript → TypeScript
absorb can be diffed against a known-good reference.

## Components

The bundle is three concatenated files (see `GetmeUK/ContentEdit@1.3.5` `Gruntfile.coffee`,
`concat.build`), joined with a single `\n` separator by `grunt-contrib-concat`:

| Lines | Component | Version | Commit |
|---|---|---|---|
| 1–1349 | HTMLString (incl. FSM) | **1.0.6** | `8ca1028b8f00c0ae20e25887e57999c7eb6fb03b` |
| 1350–1646 | ContentSelect | **1.0.3** | `3857dd67a96891a1bdb283d3a554a5b603883810` |
| 1647–5560 | ContentEdit | **1.3.5** | `8176f1d02ce083b7d23ef0b6249515324fa3a8da` |

> **HTMLString is 1.0.6, not 1.0.7.** ContentEdit 1.3.5 pins 1.0.6, and the planning notes for
> this milestone said 1.0.7. Absorbing 1.0.7 would have pulled in an unreviewed version delta.

HTMLString itself is `external/fsm.js` + its four compiled sources. **FSM has no CoffeeScript
source and no upstream repository** — `vendor-src/html-string/fsm.js` (94 lines) is the only
form it exists in, and it must be hand-converted during the absorb.

## Compiler

Compiled with **CoffeeScript 1.7.1 or 1.8.0** — both emit identical output here. It is
definitively *not* 1.9.0+, which renamed the generated helpers (`__slice` → `slice`, `__extends`
→ `extend`, `_ref` → `ref`, `_results` → `results`). Compiling with 1.12.7 yields 733 differing
lines that are purely cosmetic codegen, not semantic.

`grunt-contrib-coffee` was configured with `join: true` (concatenate *then* compile, so all
classes share one closure) and strips the `// Generated by CoffeeScript x.y.z` banner. The banner
is the only difference between a raw CLI `--join` compile and the committed build.

## Concat / compile order

Order is load-bearing — `join: true` means one shared scope, and base classes must precede
subclasses.

```
ContentEdit:   namespace tag-names bases regions fixtures root static text images videos lists tables
HTMLString:    namespace strings tags characters        (prefixed by external/fsm.js)
ContentSelect: content-select                           (single file)
```

## Reproducing

```sh
./vendor-src/verify-provenance.sh
```

Clones the three tags, compiles with CoffeeScript 1.7.1, reassembles, and diffs against
the vendored section of the frozen artifact. Exits non-zero on any mismatch.

## Inherited test suite

`vendor-src/content-edit/spec/` carries upstream's 12 Jasmine spec files, ~171 KB — roughly 8×
ContentTools' own coverage, over exactly the element/region/text/table/list semantics that
markdown round-tripping will depend on. Porting these to Vitest is a named Phase 2 work item and
is the main payment for absorbing ContentEdit.

Upstream bug to preserve awareness of: ContentEdit's `Gruntfile.coffee` lists `src/spec/bases.coffee`
**twice** in `coffee.spec`. Harmless under Jasmine; do not replicate when porting.
